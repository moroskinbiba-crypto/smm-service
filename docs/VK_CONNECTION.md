# Подключение VK к TGRML posting

В TGRML posting VK подключается без OAuth. Пользователь предоставляет ключ доступа конкретного сообщества и ID этого сообщества.

## Как получить ключ
1. Откройте нужное сообщество, где вы администратор.
2. Перейдите: Управление → Дополнительно → Работа с API → Ключи доступа.
3. Нажмите «Создать ключ».
4. Выберите права, необходимые для публикаций. Для медиа включите доступы для фото и видео, если VK показывает их отдельно.
5. Подтвердите создание и скопируйте ключ. Не отправляйте его в чат.

## Как узнать ID сообщества
Используйте числовой ID сообщества. В TGRML posting вводится ID без знака «−».
Например: VK API может использовать -123456789, а в TGRML posting нужно указать 123456789.

## Подключение в TGRML posting
Откройте Аккаунты → VK и заполните:
- Ключ доступа сообщества — ключ из настроек VK.
- ID сообщества — числовой ID без «−».
- Название в сервисе — необязательно.
После этого нажмите «Подключить аккаунт». TGRML posting сохранит ключ на сервере в защищённом хранилище и проверит доступ к сообществу.

## Важно
Для каждого сообщества используйте отдельный ключ доступа.
Если ключ отозван в VK через Управление → Дополнительно → Работа с API → Ключи доступа, публикации из TGRML posting перестанут работать до повторного подключения.
Если VK возвращает ошибку при публикации конкретного типа медиа, ориентируйтесь на текст ошибки: отдельные методы VK API могут иметь собственные требования к типу токена и доступам.

Официальная документация VK: https://dev.vk.com/ru/api/access-token/community-token

## Личная страница VK через VK ID

TGRML также поддерживает подключение личной страницы VK через официальный VK ID Web SDK. Пользователь нажимает «Войти через VK ID», проходит авторизацию и не вводит access token вручную.

Для работы нужно один раз создать Web-приложение в VK ID и указать в секретах Edge Function:

- `VK_ID_APP_ID` — ID приложения VK ID;
- `VK_ID_REDIRECT_URI` — точный доверенный Redirect URL, совпадающий с адресом возврата в приложении;
- `VK_ID_SCOPE` — права, необходимые API. По умолчанию сервис запрашивает `vkid.personal_info wall photos video offline`.

После авторизации сервис сохраняет access token и refresh token зашифрованно. Перед публикацией и при проверке аккаунта просроченный пользовательский токен автоматически обновляется через VK ID.

В интерфейсе VK теперь есть два режима: **Сообщество VK** (ключ доступа сообщества) и **Личная страница** (VK ID). Они используют разные способы авторизации и разные параметры `owner_id`, поэтому не смешиваются.
